# 06 — 專案樹重構

**What to build:** 使用者想找某個特定專案的舊 session 時，看到的是一個乾淨的、預設全部收合的專案清單（檔案總管式縮排樹），點開才看到內容；點開一個很多筆的專案或雜項時，內容依時間區間分組，不會變成一長串雜亂卡片，也不需要分頁點擊。

**Blocked by:** None — can start immediately

- [ ] 既有的手風琴摺疊分群區重構為「專案節點 → 路徑子節點 → 時間區間 → session」的階層：
  - 專案節點依 `displayName` 聚合（沿用既有分群邏輯，不改變分群本身的規則）
  - 路徑子節點只在同一專案節點下有多個 `groupKey`（同名專案存在於多個磁碟路徑）時才出現這一層
  - 雜項沒有路徑子節點這一層，直接是「雜項節點 → 時間區間 → session」
  - 時間區間分組為「今天／昨天／本週／更早」，依 `lastActiveAt` 分類
- [ ] 視覺呈現加強縮排、連接線、展開/收合圖示的樹狀感，沿用既有 `<details>/<summary>` 語意與純 CSS 實作，不引入 canvas/SVG 或外部資源
- [ ] 移除現行「預設展開最近 5 組」的邏輯；所有節點（含雜項）預設 `open = false`
- [ ] 單一節點展開後不分頁、全部顯示（不加「顯示更多」按鈕）
- [ ] 同一專案節點跨多個磁碟路徑時，仍聚合在同一個節點下顯示「（N 個位置）」，不因這次重構而改變既有的聚合行為
- [ ] 透過既有的 DOM 執行測試手法（`node:vm` + 最小 DOM stub）驗證：所有節點預設收合、時間區間分組正確、多路徑專案仍正確聚合且不分頁
- [ ] 部署後在真實資料／瀏覽器上肉眼確認：進入頁面時所有專案節點收合、點開一個大節點（例如雜項）能看到今天/昨天/本週/更早的分組、點開一個曾跨磁碟搬移的專案仍顯示所有真實路徑
