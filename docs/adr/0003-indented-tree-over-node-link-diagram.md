# 專案樹採檔案總管式縮排，不做節點連線圖

使用者最初提出希望把專案／session 的階層關係做成節點用曲線連接的樹狀圖（類似心智圖）。討論後改採檔案總管式的縮排清單（展開圖示＋連接線＋一層層往下推擠展開，沿用既有的手風琴摺疊互動），理由是：目前資料規模是 24 個專案節點、260+ session，雜項底下還有幾十筆沒有父節點的零散項目；節點連線圖在這個規模下難以閱讀，且使用者自己發現「多個節點同時展開時該放大哪一區塊」在此規模下無解，與「效率優先」的核心目標衝突。縮排樹的展開行為是往下推擠版面而非放大聚焦，不會有這個問題。

## Considered Options

- 節點連線圖（類似心智圖）：視覺上更吸睛，但在此資料規模下可讀性差，且「多個展開時放大誰」的問題沒有好解法；也需要額外的 canvas/SVG 版面配置邏輯，違反零外部依賴、單檔部署的既有架構。
- 檔案總管式縮排樹（採用）：與既有手風琴摺疊本質相同，只是加強視覺層級（縮排＋連接線＋展開圖示），可用純 CSS/DOM 巢狀結構實作，可線性擴展到數百筆項目。
